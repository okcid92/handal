ÉTAPE 1 — ALGORITHME : DÉTECTER LES PASSAGES SIMILAIRES
═══════════════════════════════════════════════════════════════

Crée le fichier :
src/server/analysis/segment-matcher.ts

Ce fichier doit exporter une fonction principale :

  findMatchingSegments(
    studentText: string,
    referenceText: string,
    options?: MatchOptions
  ): MatchResult

Avec ces types :

  interface MatchOptions {
    minSegmentLength?: number   // défaut: 20 mots
    similarityThreshold?: number // défaut: 0.75 (75%)
    windowSize?: number          // défaut: 50 mots (fenêtre glissante)
  }

  interface TextSegment {
    text: string          // le texte du passage
    startIndex: number    // position de début dans le texte original
    endIndex: number      // position de fin dans le texte original
    similarity: number    // score 0-1
    matchedSegmentId?: string // ID du segment correspondant dans la source
  }

  interface MatchResult {
    studentSegments: TextSegment[]   // passages suspects dans le doc étudiant
    referenceSegments: TextSegment[] // passages correspondants dans la source
    overallSimilarity: number        // score global 0-1
    totalMatchedWords: number        // nombre de mots copiés
  }

ALGORITHME À IMPLÉMENTER :

  Méthode 1 — N-gram sliding window (obligatoire) :
  
    1. Découper studentText en fenêtres de windowSize mots
       ex: fenêtre 1 = mots 0-49, fenêtre 2 = mots 5-54, etc.
    
    2. Pour chaque fenêtre du texte étudiant :
       a. Générer les n-grammes (trigrammes) de la fenêtre
       b. Comparer avec toutes les fenêtres du texte référence
       c. Calculer le score Jaccard entre les deux ensembles de trigrammes
       d. Si score >= similarityThreshold : marquer comme passage suspect
    
    3. Fusionner les fenêtres consécutives qui se chevauchent
       ex: si fenêtres 3,4,5 sont toutes suspectes → un seul segment
    
    4. Filtrer les segments trop courts (< minSegmentLength mots)

  Méthode 2 — LCS (Longest Common Subsequence) pour affiner :
  
    Pour chaque paire de segments détectés par la méthode 1 :
    - Trouver la plus longue sous-séquence commune
    - Calculer le score LCS = longueur LCS / max(len_A, len_B)
    - Mettre à jour le score de similarité du segment

  Fonction utilitaire nécessaire :
  
    function tokenize(text: string): string[]
    // Sépare en mots, lowercase, supprime ponctuation
    // Utilise les stopwords de content-filter.ts
    
    function generateTrigrammes(tokens: string[]): Set<string>
    // ['le','chat','dort'] → {'le_chat_dort'}
    
    function jaccardScore(setA: Set<string>, setB: Set<string>): number
    // |A ∩ B| / |A ∪ B|
    
    function mergeOverlappingSegments(segments: TextSegment[]): TextSegment[]
    // Fusionne les segments qui se chevauchent dans le texte

IMPORTANT :
- Ne jamais retourner d'erreur sur texte vide (retourner MatchResult vide)
- Performance : limiter à 500 fenêtres max par document (textes longs)
- Timeout : si l'analyse dépasse 10 secondes, retourner ce qu'on a

ÉTAPE 2 — MISE À JOUR DE L'ANALYSEUR PRINCIPAL
═══════════════════════════════════════════════════════════════

src/server/analysis/plagiat-detector.ts

Ajoute dans le type AnalysisResult :

  interface AnalysisResult {
    // ... champs existants à conserver ...
    globalSimilarity: number
    riskLevel: 'low' | 'medium' | 'high'
    
    // NOUVEAU : segments détaillés par source
    matchedSources: MatchedSource[]
  }

  interface MatchedSource {
    sourceId: string           // ID du document de référence en DB
    sourceTitle: string        // Titre du document de référence
    sourceSimilarity: number   // Score global avec cette source (0-1)
    studentSegments: TextSegment[]   // passages dans le doc étudiant
    referenceSegments: TextSegment[] // passages correspondants dans la source
    totalMatchedWords: number
  }

Dans la fonction principale d'analyse :

  1. Pour chaque document de référence en DB :
     a. Récupérer son extractedText depuis ReferenceDocument
     b. Appeler findMatchingSegments(studentText, refText)
     c. Si overallSimilarity > 0.15 : ajouter à matchedSources
  
  2. Trier matchedSources par sourceSimilarity décroissant
  
  3. Garder au maximum les 5 sources les plus similaires
     (éviter une réponse JSON trop lourde)

  Cette fonction :
  1. Trie les segments par startIndex croissant
  2. Découpe le texte en tranches :
     - Texte normal → <span>{texte}</span>
     - Passage suspect → 
       <mark 
         className="bg-red-200 border-b-2 border-red-500 
                    cursor-pointer rounded px-0.5"
         title={`Similarité : ${segment.similarity}%`}
         data-segment-id={index}
       >
         {texte}
       </mark>
  3. Pour la source, utiliser bg-yellow-200 border-yellow-500
     au lieu de bg-red-200 border-red-500

COULEURS :
  - Passages dans le doc étudiant : rouge
    bg-red-100 border-red-400 (similarité 75-89%)
    bg-red-300 border-red-600 (similarité 90-100%)
  
  - Passages dans la source : jaune
    bg-yellow-100 border-yellow-400
  
  - Score affiché dans un badge :
    vert si < 20%, orange si 20-70%, rouge si > 70%

INTERACTIONS :
